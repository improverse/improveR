## 🏗️ **Major Architectural Change**

### Package Consolidation
The improveR package ecosystem has been restructured for better maintainability and clearer separation of concerns:

**Previous Structure (v1.3.0):**
```
├── improveRcore         # Core read-only functionality
├── improveRmodify       # Write/modify operations
├── improveRadmin        # Administrative functions
```

**New Structure (v4.3.1):**
```
improveR/                # Single unified package (OPEN SOURCE)
├── Core API             # Connection, authentication, data access
├── Write Operations     # Create, update, delete with setEditable() guard
├── Workflow Management  # Steps, workflows, templates
├── CLI Tools            # Command-line utilities (clone, push, pull)
└── Review System        # Code review and collaboration
```

**Benefits:**
- Simplified dependency management
- Clearer API with single import: `library(improveR)`
- Better documentation and discoverability
- Unified versioning

**Migration Required:**

⚠️ **Breaking Change:** The separate packages `improveRcore`, `improveRmodify`, and `improveRadmin` are no longer available. All functionality has been consolidated into the single `improveR` package.

**Before (v1.3.0):**
```r
library(improveRcore)    # Core functionality
library(improveRmodify)  # Write operations
library(improveRadmin)   # Admin functions
```

**After (v4.3.1):**
```r
library(improveR)  # Everything in one package
```

**Action Required:**
1. Remove references to `improveRcore`, `improveRmodify`, and `improveRadmin` from your scripts
2. Replace with single `library(improveR)` call
3. All function names remain the same - no code changes needed beyond the library() statement

## 🔒 **New Write Protection System**

### `setEditable()` Function
Introduces explicit write-mode control for safer repository interactions:

```r
# Connect to improve server (read-only by default)
improveConnect()

# Enable write operations
setEditable(TRUE)

# Now you can modify the repository
createFolder("/Projects/MyAnalysis")
updateFileContent(...)

# Disable write operations when done
setEditable(FALSE)
```

**Key Features:**
- **Default read-only:** All connections start in safe read-only mode
- **Explicit opt-in:** Write operations require conscious enablement
- **Guard function:** `improveEditable()` validates write permission before modifications
- **Session-scoped:** Editable state persists for session duration

**Protected Operations:**
- Creating resources, steps, and workflows
- Updating files and metadata
- Deleting resources
- Locking/unlocking resources

## 🔄 **API Changes**

### Breaking Changes

**1. Terminology Standardization: "lineage" → "dependencies"**
Renamed throughout the entire codebase for clarity:
```r
# Old (1.3.0):
createWorkflow(..., lineage = "step1,step2")

# New (4.3.1):
createWorkflow(..., dependencies = "step1,step2")
```

**Migration:** Update any code using "lineage" parameters to "dependencies".

**2. Write Operations Now Require `setEditable(TRUE)`**
All write operations now check for explicit write permission:
```r
# Old (1.3.0):
improveConnect()
createFolder(...)  # Worked immediately

# New (4.3.1):
improveConnect()
setEditable(TRUE)  # Required for write operations
createFolder(...)  # Now works
```

**Migration:** Add `setEditable(TRUE)` after `improveConnect()` in scripts that modify the repository.

```r

```

**b) Add `setEditable()` for Write Operations**
```r
# Add after improveConnect() in scripts that modify the repository:
improveConnect()

```

**3. Test Your Workflows**
```r

# ... test other operations
```

**4. Review New Features**
- Check out the new `setEditable()` safety mechanism
- Explore updated pkgdown documentation
- Try the new parental descendant functions

### Troubleshooting

**"improve is connected but the editable flag was not set"**
- **Cause:** You're trying to write without enabling write mode
- **Fix:** Call `setEditable(TRUE)` before write operations

**"Argument 'lineage' not found"**
- **Cause:** Using old v1.3.0 parameter name
- **Fix:** Change `lineage =` to `dependencies =`

**Connection issues after upgrade**
- **Fix:** Disconnect and reconnect:
  ```r
  improveDisconnect()
  improveConnect()
  ```
